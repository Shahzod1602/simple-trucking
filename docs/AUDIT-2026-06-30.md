## 1. Qisqa xulosa

Poydevor **sog'lom**: SQL hamma joyda parametrlangan (injection topilmadi), tenant-scoping asosiy o'qish yo'llarida to'g'ri, parollar Argon2id, Telegram MTProto sessiyalari Fernet bilan shifrlangan, bot/email poller'lari advisory-lock singleton, login per-IP throttle bor, pul agregatsiyasi asosan crash-safe `_rate_to_numeric` + generated NUMERIC ustunlar orqali, jonli secret'lar gitignore'da.

Jiddiy muammolar **uch sohada** to'plangan:
1. **Global superadmin** — jonli `.env` da paroli `1234567890`, account-lockout ham, MFA ham yo'q → bitta lug'at-paroli butun platformani egallashga yetadi.
2. **Frontend XSS** — bir nechta stored-XSS sink, CSP umuman yo'q, bearer token localStorage'da; jumladan **auth'siz** "kompaniya nomi orqali → superadmin'ni egallash" zanjiri.
3. **Email OAuth connect/callback** — tenant-bog'lovchi `state` zaif/hardcoded secret bilan imzolangan, callback mailbox egaligini jimgina qayta tayinlaydi → cross-tenant mailbox hijack.

Atrofida: UNIQUE-constraint yo'qligidan kelib chiqadigan dublikat-poyga (akkaunt/daromad/KPI ikki marta), bitta sekin ELD provayder hamma worker'ni muzlatadigan blocking loop, secret-at-rest va infra-hardening kamchiliklari, va bir nechta invoice/moliya to'g'rilik buglari.

Hech bir CRITICAL **faqat repo'dan** exploit qilinmaydi — lekin aksariyati **jonli (on-disk/deployed) konfiguratsiyada faol**. Xulosa: arxitektura yaxshi, lekin multi-tenant SaaS sifatida ishlashidan oldin bir nechta yuqori-ta'sirli xavfsizlik nuqsonini **darhol** yopish kerak.

## 2. CRITICAL

### C1 — Superadmin paroli `1234567890` (jonli), lockout/MFA yo'q
`.env` (`SUPER_ADMIN_PASSWORD=1234567890`); `database.py:502-521` (`ensure_superadmin`, kuch tekshiruvi yo'q); `app.py:49-51` (har startup'da qayta yoziladi), `app.py:497-523` (login, faqat per-IP throttle).
Yagona global superadmin (cross-tenant console: kompaniyalar CRUD, istalgan kompaniyada user yaratish/o'chirish, istalgan parolni reset, barcha load/driver/ELD-kalit/mailbox/Telegram-sessiya) eng keng tarqalgan 10-raqamli parol bilan himoyalangan. `ensure_superadmin` kuch tekshirmaydi va **har boot'da qayta yozadi** (qo'lda rotatsiyani bekor qiladi). Per-account lockout yo'q, MFA yo'q.
**Fix:** parolni 32+ belgili random'ga rotatsiya (har muhitda); `ensure_superadmin` ichida minimal uzunlik/murakkablik majburlash; per-account lockout + MFA yoki IP-allowlist.

### C2 — Auth'siz stored XSS superadmin console'da (kompaniya nomi → onclick breakout) → to'liq platforma egallash
`templates/admin.html:504-507` (`renderCompanies`), `:636,640` (`renderUsers`), `esc()` `:449`; `app.py:473-489` (`/api/register` istalgan bo'sh-bo'lmagan `company_name` qabul qiladi); `database.py:1541-1546` (xom saqlaydi).
`onclick='openAssign(${c.id}, ${JSON.stringify(c.name)})'` — `JSON.stringify` ikkilik tirnoqni escape qiladi, lekin **bitta tirnoqni emas**. `x' onmouseover='fetch(...)+localStorage.st_token` nomli kompaniya o'zini ro'yxatdan o'tkazadi; superadmin Companies ro'yxatini ochganda (yoki sichqonchani ustiga olib borganda) payload superadmin sessiyasida ishlaydi. CSP yo'q + token localStorage'da → exfiltratsiya → barcha tenant'lar egallanadi. Ko'rinadigan katak `esc()` ishlatadi — demak encoder bor, faqat onclick'ga qo'llanmagan.
**Fix:** untrusted satrni inline handler'ga qo'ymang — `addEventListener` + `esc()`'langan `data-*`, yoki faqat raqamli id uzating; qattiq CSP (`script-src 'self'`); server-tomonda `company_name` charset cheklov.

## 3. HIGH

### H1 — `ensure_superadmin` bo'sh-credential guard'siz; lifespan chaqiruvi init_db guard'ini chetlab o'tadi → noto'g'ri-konfig'da parolsiz superadmin
`app.py:47-52`; `database.py:496-499` (guard faqat init_db'da), `:502-521`.
`init_db` `if super_email and super_pass` bilan himoyalangan, lekin lifespan `ensure_superadmin(getenv(...,''), getenv(...,''))` ni **shartsiz** chaqiradi. Ikkala env unset bo'lsa, `email=''` + `''` ning argon2-hash'i bilan superadmin satri INSERT bo'ladi → auth'siz `POST /api/login {"email":"","password":""}` superadmin sessiya beradi. Jonli `.env` to'ldirilgan, lekin yangi/staging/qisman-konfig deploy zaif.
**Fix:** `ensure_superadmin` boshiga `if not (email and password): return` + min-uzunlik; lifespan chaqiruvini init_db kabi gate qiling.

### H2 — Cross-tenant mailbox hijack: zaif/hardcoded OAuth state-secret + auth'siz callback egalikni qayta tayinlaydi
`app.py:2979-2984` (`_email_state_secret` → `SUPER_ADMIN_PASSWORD` keyin `'ratecon-dev-state-secret'`), `:2987-3008` (900s TTL, nonce yo'q), `:3029-3046` (callback auth'siz); `database.py:2086-2099` (`create_email_account` `ON CONFLICT DO UPDATE SET company_id = EXCLUDED.company_id`).
Tenant-bog'lovchi HMAC kaliti `SUPER_ADMIN_PASSWORD` (jonli=`1234567890`) yoki manbada chop etilgan `'ratecon-dev-state-secret'` ga tushadi. Ma'lum kalit bilan istalgan `company_id` uchun `state` qalbakilashtirish mumkin; callback attacker-uzatilgan `accountId/email/provider` ni ishonadi va `ON CONFLICT` mavjud `relay_account_id` ni qalbaki kompaniyaga **jimgina ko'chiradi**. State 15 daqiqa replay bo'ladi (single-use nonce yo'q). Natija: jabrlanuvchining email'i attacker mailbox'iga tushadi (o'qish/javob) yoki jabrlanuvchi tenant'iga attacker-mailbox in-product fishing uchun in'ektsiya qilinadi.
**Fix:** alohida yuqori-entropiyali `RELAY_STATE_SECRET` (unset bo'lsa fail-closed); `SUPER_ADMIN_PASSWORD`/konstanta ishlatmang; state single-use (nonce/jti) + dispatcher va account'ga bog'lash; `create_email_account` — `relay_account_id` boshqa kompaniyaniki bo'lsa **rad eting**, jimgina ko'chirmang.

### H3 — Stored XSS: email attachment same-origin, sandbox'siz iframe'da (broker boshqaradigan Content-Type) → account takeover
`templates/index.html:3795` (`isPdf` fayl nomi bo'yicha), `:3851-3869` (iframe, sandbox yo'q, `blob:` URL); `app.py:3166-3169` (`media_type=content_type` passthrough); `relay.py:103`.
Server attachment'ni broker-boshqaradigan MIME bilan qaytaradi. `isPdf` faqat fayl nomi `.pdf` bilan tugashini tekshiradi → klient `blob:` (same-origin) iframe'ni **sandbox'siz** yuklaydi. Broker `invoice.pdf` nomli, lekin `Content-Type: text/html` + script bo'lgan part yuboradi; "Open" bosilganda HTML app origin'da ishlaydi, localStorage token'ni o'qiydi → takeover. CSP yo'q.
**Fix:** attachment baytlarini same-origin iframe'da render qilmang — `sandbox=""` (allow-scripts'siz); preview `media_type` ni `application/pdf` ga majburlang (text/html rad); `blob.type==='application/pdf'` tekshiring; Relay content-type'iga ishonmang; qattiq CSP.

### H4 — Tenant SPA'da bir nechta stored-XSS sink (Live Loads escape'siz + onclick single-quote breakout'lar)
`templates/index.html:6353-6360` (`loadLiveLoadsPage` — `load_number/broker_name/origin/destination/total_rate_usd/eta` escape'siz), `:5696` (load_number onclick), `:7462` (POD fayl nomi onclick), `:4118/:5143/:5146` (user-name onclick); `extractor/validator.py:33,40-45` (load_number charset cheklov yo'q).
(1) Live Loads jadvali `esc()`'siz innerHTML quradi — broker ratecon PDF'idan kelgan `<img onerror=...>` load_number dispatcher/admin Live Loads'ni ochganda ishlaydi. (2) Single-quoted onclick'da `JSON.stringify` — broker load_number, yuklangan POD fayl nomi yoki past-huquqli user nomidagi bitta tirnoq handler in'ektsiya qiladi (low-priv → admin eskalatsiya). CSP yo'q + token localStorage'da.
**Fix:** `loadLiveLoadsPage` da har qiymatni `esc()` (xuddi `renderLoadsTable` kabi); inline onclick → `addEventListener`+`data-*` yoki faqat id; fayl nomi/load_number charset cheklov; qattiq CSP.

### H5 — Truck-prefetch background loop har worker'da (lock yo'q) + event-loop'ni sync ELD HTTP bilan bloklaydi
`app.py:68-69` (`create_task`, lock yo'q), `:191-202` (`_prefetch_trucks_loop`), `:177-188` (`_retry_sync_call` `time.sleep`); `eld/motive.py:31-37`, `samsara.py:24`, `zippy.py:52` (sync `httpx.get`); `Dockerfile:18` (`--workers 4`).
Bot/email poller'laridan farqli, prefetch loop **4 worker'da ham** ishga tushadi → har dispatcher ELD'si 4× uriladi, DB 4× so'raladi (har 20s). Yomoni: bloklovchi sync httpx (+ `time.sleep` retry) to'g'ridan-to'g'ri async loop ichida → bitta provayder osilsa worker event-loop ~30s muzlaydi (10s × 3 × bir nechta config), o'sha worker'dagi BARCHA so'rovni (login, extract, boshqa tenant) to'xtatadi. Kod allaqachon geocode'da `asyncio.to_thread` ishlatadi — bu izolyatsiyalangan nuqson.
**Fix:** uchinchi advisory-lock kaliti bilan guard; `await asyncio.to_thread(_get_dispatcher_trucks, ...)` (yoki async httpx); dispatcher'lar orasiga `await asyncio.sleep(0)`.

## 6. DARHOL qilinadigan ishlar (ustuvorlik bo'yicha)

1. **`SUPER_ADMIN_PASSWORD` ni kuchli random'ga rotatsiya** (har muhitda) + `ensure_superadmin` da min-uzunlik majburlash. *(C1)*
2. **Superadmin-console XSS** (admin.html company-name onclick) ni tuzatish: `esc()`+`addEventListener`+`data-*`, `company_name` server-charset, qattiq CSP. *(C2)*
3. **Email OAuth connect/callback** ni qulflash: alohida `RELAY_STATE_SECRET` (fail-closed), state single-use + dispatcher/account-bog'lash, `ON CONFLICT` da `company_id` ko'chirmaslik. *(H2)*
4. **Qolgan XSS sink'lar** (Live Loads, onclick breakout'lar, email-attachment iframe) + qattiq CSP + token'ni localStorage'dan chiqarish. *(H3, H4, L6)*
5. **`ensure_superadmin` empty-credential guard** + lifespan chaqiruvni gate. *(H1)*
6. **ELD kalitlarni at-rest shifrlash** + Postgres parolini de-hardcode/rotatsiya. *(M5, M6)*
7. **Truck-prefetch loop'ni `asyncio.to_thread` + advisory-lock** (Argon2 + Zippy N+1 ni ham offload). *(H5, M9, M10)*
8. **Yo'q UNIQUE constraint'lar**: `dispatchers(LOWER(email))`, partial `loads(dispatcher_id, motive_dispatch_id)`, partial `kpi_entries(company_id, load_id)`. *(M2, M3, M4)*
9. **`/api/health` → 503** DB o'lganda; app portni `127.0.0.1` ga; proxy-IP + shared rate-limit. *(M14, M15, M8)*
